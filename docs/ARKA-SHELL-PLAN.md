# Arka Shell on KWin: plan

Status: Option A chosen (2026-10-12). Step 1, the panel surface, is built as
a Plasma style (see "What the first prototype showed"). The launcher shipped on
2026-10-20 as a Plasma widget, `org.arkaos.launcher` (see "The launcher"); the
shell package itself is not shipped yet.

The desktop direction (decided 2026-10-05) is to keep KWin as the compositor and
give ArkaOS its own shell: the panel, dock, launcher and notification look. An
ArkaWM prototype on Smithay stays a separate research track. This document
picks how to build the shell.

## What a shell has to provide on KWin

Replacing the visible parts is the easy half. Plasma's shell process
(`plasmashell`) also runs things people only notice when they break:

| Piece | Today, in plasmashell |
|---|---|
| Panel, dock, launcher | Plasma panel, Crystal Dock, `org.arkaos.launcher` (was `kickerdash`) |
| Window list for the dock | Plasma task manager model (KDE window-management protocol) |
| System tray | StatusNotifierItem host |
| Notifications | notification server and popups |
| Volume and brightness popups (OSD) | plasmashell OSD |
| Desktop and wallpaper | desktop containment |
| Accessibility, portals, screencast, multi-monitor, scaling | KWin and Qt, unchanged by either option |

## Option A: an ArkaOS Plasma shell package (recommended first)

Plasma loads its whole shell from a QML "shell package"; Plasma Mobile, Plasma
Bigscreen and Plasma Nano are alternative shell packages on the same
`plasmashell`. ArkaOS ships `org.arkaos.desktop` with its own panel, dock,
launcher and notification views, and keeps KDE's tray host, notification
server, OSD, task models and accessibility.

- Language: QML (plus small C++ only if a model is missing).
- Effort: about 1 to 2 weeks for panel, dock and launcher; notifications and
  OSD styling after that.
- Risk: low. Falls back to the stock desktop package if a file is missing.
- Trade-off: the shell is QML, not Rust; the ArkaOS apps stay Rust/GTK.

## Option B: Rust/GTK layer-shell programs instead of plasmashell

Revive (from git history, up to 0d707ca) `legacy/arka-bar`, `arka-dock` and `arka-launcher` (about 1,400 lines,
gtk4-layer-shell). KWin supports the layer-shell protocol, so the surfaces
work. The rest has to be rebuilt:

- the dock's window list needs `org_kde_plasma_window_management`, which KWin
  only gives to programs that request it in their desktop file;
- a StatusNotifierItem host for the tray;
- a notification server and popups;
- volume and brightness popups;
- desktop and wallpaper.

- Effort: several weeks before it reaches what Plasma gives today.
- Risk: high; each missing piece is a regression people will notice.

## Recommendation

1. Build Option A: panel surface in the ArkaOS Plasma style (done), then the
   dock and launcher views in an `org.arkaos.desktop` shell package, matching the setup app and Privacy dashboard look (light first,
   Light/Dark choice, no glow or glass).
2. Style notifications and OSD within the same package.
3. Use Option B only for a piece QML cannot do well, one piece at a time.
4. Keep the ArkaWM (Smithay) prototype as research; it replaces KWin only after
   it matches KWin on accessibility, portals, screencast, multi-monitor,
   scaling and XWayland.

## What the first prototype showed (2026-10-12, Plasma 6.7.5, VM)

- A shell package works with only the files it changes: its metadata can name
  `X-Plasma-FallbackPackage` (libplasma `shellpackage.cpp`), and
  `plasmashellrc` `[Shell] ShellPackage` selects it. The lock screen and every
  other view came from the stock package.
- Drawing the panel background in the shell's `Panel.qml` is the wrong layer.
  PanelView takes the blur region, background contrast and shadows from the
  Plasma style's `widgets/panel-background` SVG, so a QML-drawn rounded panel
  kept a square halo behind it.
- So the panel surface ships as a Plasma style: `arkaos-dark` and
  `arkaos-light` keep Breeze's colours and replace only `panel-background`
  (24px corners, 1px border, soft shadow, generated by
  `plasma-style/make-panel-svg.py`). Shape, blur and shadow then match.
- Plasma keeps panels per shell (`plasma-<shell>-appletsrc`), and
  `plasmashell` exits if the selected shell package is missing. The shell
  package should ship only once it carries a view of its own (the launcher or
  dock), for new accounts only, so existing panels are not reset.
- Plasma uses the same shadow tiles for every panel, so the flat top bar and
  the floating dock share one soft shadow rather than the design system's
  heavier floating-surface shadow.

## Popups (2026-10-20)

Every popup Plasma draws (notifications, the volume and brightness popups, the
tray, calendar and launcher) takes its frame from the Plasma style's
`dialogs/background`. `plasma-style/make-panel-svg.py` now writes that file
too, so all of them change without replacing any KDE component. Four looks
were compared in the VM (round corners, cut corners, an accent line, a flat
outline); cut corners were chosen because they echo the ArkaOS mark and no
other desktop uses them. Corners are cut at 45 degrees (10px), with a 1px
border and a softer, wider shadow than the panel's. Popups attached to the top
bar keep a square edge against it, as in Breeze. The launcher's own search
field, highlights and tiles use the same shape (`CutRect.qml`).

## The launcher (2026-10-20)

The launcher is a Plasma widget (`plasma-launcher/`, installed as
`org.arkaos.launcher`), not a view in a shell package. A widget needs no new
shell, so existing panels keep working, and Plasma's *Show Alternatives* swaps
it with Kickoff, Kicker or the Application Dashboard in either direction.

- Data comes from Plasma's own models (`org.kde.plasma.private.kicker`): the app
  list and categories, search (only the `krunner_services` and
  `krunner_systemsettings` runners, so it searches what its placeholder says),
  and pinned apps. Session buttons use `org.kde.plasma.private.sessions`, which
  shows KDE's usual confirmation.
- Pins are KActivities resources shared by every launcher of an account, so an
  account that switches keeps its pins. New accounts get the list in
  `/etc/xdg/kicker-extra-favoritesrc`; Fedora's kde-settings ships its own
  (Kontact, KWrite) with `IgnoreDefaults=true`, and `/etc/xdg` is read first.
- The privacy line runs `arka-privacy-tray --status`, which prints the tray's
  level and header from one fresh reading, so the launcher never words the
  status differently from the tray.
- Colours come from the Plasma colour scheme, so Light, Dark and a user's own
  scheme all apply.

Tested in a VM on 2026-10-20 (image 8337693a with the files copied in): open by
click and Meta, search and Enter, arrow keys between search, categories and
apps, pin and unpin, launching, the privacy line opening the Dashboard, Lock,
Log Out and Shut Down prompts, Light, Dark, 150% scaling, and a new account
getting the ArkaOS pins. On 2026-10-20 the published image (8fb95e41) passed
the same checks, and two virtual screens worked once the bar came to every
screen (`panels/`). Not yet tested: a screen reader, real monitors, real
hardware.

## A bar on every screen (2026-10-20)

Plasma does not give a newly connected screen a panel. `arka-layout.js` adds
the top bar to each screen at first login; `arka-panels` runs it again, in a
mode that only adds bars, at every login (a user service) and whenever KWin
reports a change of screens (the `arka-panels` KWin script starts that
service). Each screen's desktop remembers that it got a bar, so a bar the user
removes is not added back. A second screen's bar uses the launcher the account
already has, so an account that kept KDE's menu gets KDE's menu there too.

## Done means (each step, in a VM, then on hardware)

- Panel, dock and launcher open, close and survive a restart, in Light and Dark.
- Tray icons (network, sound, the Privacy tray) and notifications still work.
- Screen reader and keyboard navigation still reach every control.
- Two monitors and 150% scaling lay out correctly.
- Removing the package returns the stock Plasma desktop.
