The stack

One image, top to bottom.

The whole OS is declared in a single container image and deployed with bootc and composefs. The root filesystem is read-only at runtime; updates are atomic and roll back to a byte-identical prior state. No configuration drift — the machine you boot is the image you built.

arka — Sanskrit for ray of light. The daemon at the center of the stack, arkad, is the layer that keeps the light yours: it enforces privacy invariants and re-checks them every 60 seconds.

What it actually does

Defense that ships turned on.

Four load-bearing guarantees — each verified in a booted image, not just compiled.

01

Read-only root

composefs mounts the root filesystem read-only and structurally immutable. Upgrades are atomic through bootc; a bad update rolls back to the exact previous image.

02

Rust privacy daemon

arkad — a static musl binary — continuously enforces MAC randomization, DNS-over-TLS to Quad9, a masked hostname, and IPv6 temporary addresses. It re-verifies every 60s and re-enforces on drift.

no tokio · no shell interpolation · secure defaults with no config file
03

Sandboxed browser

Firefox runs inside a bubblewrap jail: your real home is hidden behind a tmpfs, network credentials and machine-id are absent, and only ~/Downloads is bound back in.

04

Measured boot

TPM measurements cover PCRs 0–10 with a composefs-pinned root, establishing a hardware root of trust for the boot chain.

honest status: PCR 11–15 (UKI) pending real-hardware validation
