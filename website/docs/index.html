    01

    What is ArkaOS?

    ArkaOS is an independent Linux desktop built on the Fedora bootc immutable image foundation. The runtime root filesystem is read-only, updates are atomic, and the previous image stays bootable. On top of that foundation it adds two system services of its own — arkad for privacy enforcement and arka-pulse for reliability monitoring — and ships a KDE Plasma desktop.

    The premise is narrow on purpose. Privacy settings that a careful user would configure by hand are applied by default and re-checked while the system runs. The system can describe its own state, and it can be returned to a known-good one.

    WHY NOT JUST FEDORA KDE?

    ArkaOS
= proven Linux foundation
+ opinionated privacy enforcement
+ reliability layer
+ recoverable system
+ Arka-specific desktop experience
+ transparent verification

    Fedora KDE with a weekend of hardening gets you close on privacy. It does not give you enforcement that survives reboots and updates, a service that reports degradation, or a published list of what is unproven.

    What ArkaOS is not

    • ○It is not anonymity software. It does not route your traffic, and it cannot make you untrackable.
    • ○It is not a hardened security distribution or a replacement for threat-model-specific tooling.
    • ○It is not production ready. There is no graphical installer and no hardware compatibility guarantee.
    • ○It is not a Linux fork. The kernel, drivers and desktop come from upstream.

    02

    Getting started

    There is no installer ISO. Three routes work today. Start with the virtual machine unless you are testing hardware support on purpose.

    Run in a VM RECOMMENDED

    QEMU/KVM with 4 GB of RAM and 40 GB of disk. Nothing touches your host disk, and rollback is safe to test.

    qemu-system-x86_64 \
  -enable-kvm -m 4096 -smp 4 \
  -bios /usr/share/OVMF/OVMF_CODE.fd \
  -drive file=arkaos-preview.qcow2,if=virtio

    Boot from USB PREVIEW TESTING

    For development testing only. Real-hardware testing has begun, but the set of validated machines is small. Wi-Fi firmware, discrete GPUs, suspend/resume and display scaling are all known to vary. Assume you may need a wired connection and a second machine to read logs.

    sudo dd if=arkaos-preview.raw of=/dev/sdX \
  bs=4M status=progress oflag=direct

    Check the device path before running dd. It will overwrite whatever it points at.

    Build from source CONTRIBUTORS

    The image is a container build. Building it yourself is the only way to read exactly what is in the system you are booting.

    git clone https://github.com/thulasiramk-2310/Arka
cd Arka
podman build -t arkaos:dev .
bootc-image-builder --type qcow2 arkaos:dev

    FIRST RUN

    A graphical first-run setup is being developed and validated. In the current preview, expect to confirm some settings from a terminal. arkad applies its privacy state before the desktop session starts either way.

    04

    How ArkaOS works

    Seven layers. The lower five are upstream Linux infrastructure; ArkaOS owns the two in the middle and the experience above them.

    arkad · privacy daemon

    A system service that applies a fixed privacy state at boot and re-checks it while the machine runs. If something resets a setting, arkad puts it back and records that it did.

    $ arkactl status
arkad                  enforcing
mac-address            randomized
dns                    dot · 9.9.9.9 (quad9)
hostname               masked
ipv6                   privacy addresses
browser-sandbox        bubblewrap · firefox
last re-check          14s ago

    What this does not do: it does not hide your IP address from sites you visit, and DNS-over-TLS moves your resolution to Quad9 rather than making it unobservable.

    arka-pulse · reliability layer

    Local reliability monitoring and prediction. Currently focused on telemetry, detection, prediction and verification; recovery actions remain constrained and experimental. Nothing is sent off the device.

    • ●Telemetry — disk, memory, thermals, service failures, journal patterns, collected locally.
    • ●Detection — degradation surfaced with the signal that triggered it.
    • ◐Prediction — early warning ahead of failure. Thresholds are still being calibrated.
    • ◐Verification — confirming the system is in the state it reports.
    • ○Autonomous recovery — not shipped. arka-pulse recommends; you decide.

    Updates & rollback

    The OS is delivered as a container-native image. An update fetches a new image and stages it; you boot into it. The previous image remains on disk and bootable, so recovery is a reboot rather than a repair session.

    $ bootc upgrade          # stage the next image
$ systemctl reboot       # boot into it
$ bootc rollback         # return to the previous image
